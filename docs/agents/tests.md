# Tests

`bun test` is the target and the only runner a push waits on; `npm test` (Node's runner, the `test` script) is CI's second opinion, and upstream only has that one. Compare failures, never totals: Node counts subtests and suites of its own accord, so the same tree reports a different number of tests on each runner.

GitHub CI runs on pushes to `main` and `dev`, and on pull requests (`.github/workflows/ci.yml`). A `dev` push therefore runs the same checks and browser jobs before it is merged; watching a push to any other branch requires a pull request.

## What behaves differently under Bun, and what to use instead

| Node | Bun | Use |
| --- | --- | --- |
| One process, one `globalThis`, one module registry **per test file**. | One of each for the **whole suite**, files in sequence. | Whatever a file puts on `globalThis` or into the registry, it hands back in `after()` (`node:test`). A file that never restores is the next file's failure. |
| The tests of one file run one at a time, so a case may point a process-wide knob such as `PI_CODING_AGENT_DIR` at its own folder for the length of its own body. | They start at once, so whichever case set the knob last answers every other case's read of it: upstream's `lib/subagent-package-scope.integration.test.mjs` failed here with `Unknown or disabled subagent profile` while passing on Node's runner. | A file that owns a process-wide knob queues its own cases — `oneAtATime()` in that file chains one case's end to the next case's start — and `{ timeout: … }` covers the first one's cold imports. A file that reads such a knob instead of writing it needs no queue. |
| jiti `tryNative` off, so jiti resolves every import. | jiti detects Bun and turns `tryNative` on: the module is imported natively, its `import`s answered by Bun — an `alias` never applies, and jiti hands back Bun's sealed ESM namespace. | `createJiti(url, { tryNative: false })`; add `interopDefault: false` to write into a module's exports. |
| A module two files load: each gets its own copy. | The same instance, with whatever the first file left on it. | `delete createRequire(import.meta.url).cache[realpathSync(fileURLToPath(...))]` for each module the file stubs, before jiti loads it. |
| A source `.ts` that imports a sibling by its extensionless name reaches a test only through a loader that fills the extension in. | Bun resolves the extensionless path, so a test's direct `import … from "./x.ts"` is green here and says nothing about Node, where the file dies with `ERR_MODULE_NOT_FOUND` before its first test. | Load the module under test through jiti (`createJiti(import.meta.url, { tsconfigPaths: true })`, then `await jiti.import("./x.ts")`) unless every runtime import in its graph names a file with its extension: such a test writes a plain `import … from "./x.ts"` and needs no loader (70 test files do, over the 59 lib modules whose imports were given extensions). A graph that keeps one extensionless specifier, or any `@/` alias, still needs jiti — Node has no tsconfig `paths` — and so does one whose module uses parameter properties, which `--experimental-strip-types` refuses. Code arriving from upstream names those specifiers without their extension: when a merge brings it in, give every runtime import under `lib/` its `.ts`, and leave the extensionless form where something other than Node reads it — `hooks/` and `components/`, which the bundler and a fixture's own `require` compile, and a client-safe specifier a test matches by its text (`lib/session-reader.ts`). The same trap sits inside `lib/`: `lib/terminal-manager.test.mjs` runs that module in a vm whose `require` answers `"./terminal-bun-pty"`, `"./paths"` and `"./home-dir"` by exactly those ids, so its three imports keep no extension either — a test Bun cannot fail, since the real backend works there. |
| `import { readFile } from "node:fs"` reads a live property, so `t.mock.method(fs, "readFile")` reaches it. | A named builtin import is bound to a frozen snapshot: the mock never lands. | Import the builtin's default and read `fs.readFile` at call time. |
| `module.stripTypeScriptTypes()`. | Not exported, and not a global. | `runStripped(code, context)` from `lib/__fixtures__/strip-types.mjs` — jiti's transform, one path on both runtimes, and unlike Bun's own transpiler it keeps a top-level function expression as the completion value. |
| `module.registerHooks()` to answer a `.module.css` import. | Not exported; Bun loads CSS modules itself. | Install the hook only `typeof registerHooks === "function"`. |
| `fetch` goes through undici's global dispatcher, and jiti's CJS interop finds `undici.install` so `configureHttpDispatcher()` can point fetch at it. | Bun's own `fetch`: it installs no dispatcher (`configureHttpDispatcher()` is a no-op here), takes its proxy from the request or `$HTTP_PROXY` / `$HTTPS_PROXY` — for `127.0.0.1` too — and resolves no `install` out of `undici`, so `undici.install?.()` would skip silently. | Prove a port is closed with `connect()` from `node:net`, never with `fetch`. Assert the dispatcher's contract on Node only, and say so in the test. Never let an optional call be the only thing that makes a branch work on one runtime. |
| No per-test timeout by default. | 5 s. | `{ timeout: … }` where a test waits on something genuinely slow. |
| `t.mock.method(globalThis, "fetch", …)` and then a second `t.mock.method` on the same property inside one test: both come back when the test ends. | Only the outermost mock is restored; the inner stub stays installed on `globalThis` and answers every later file's real requests, so an unrelated file fails with the first stub's error (`Unexpected network request`) while the file that mocked it is green. `globalThis.fetch === original` proves nothing here either: Bun answers each read with a fresh function. | Mock the property once per test and let the test swap what the stub does (`lib/rpc-manager-model-config.integration.test.mjs` and its `stubFetch`). |
| A test that swaps one `globalThis` key twice, each swap restoring what it replaced in `t.after`: the hooks run in the order the swaps were made, so the last restore writes back what the *first* swap installed. | Same order, and it reaches the next file, which shares the `globalThis`: `/api/project-trust` answered 500 because `session.cwd` had read a fake wrapper's absent `sessionManager` off the registry the previous file left live. | Capture a key's original once, on the first swap of it, and have every restore — per test and at the end of the file — write that one back: `createPiGlobalSwaps()` (`lib/__fixtures__/pi-global-swap.mjs`), used by `lib/debug-snapshot.test.mjs` and `lib/rpc-manager-debug.test.mjs`. |
| A keep-alive connection a proxy recycles just ends the request. | `node:http` errors the request stream, so a fixture server that reads `req.body` unguarded raises an unhandled rejection — attributed to whichever test is running. | Guard the body read in the fixture (`lib/__fixtures__/mcp-oauth-server.mjs`). |
| The product state a module keeps on `globalThis` (`__piWebScanIndex`, `__piWebProviderModelCatalog`, `__piWebTerminals`, …) is that file's alone. | It is the suite's. Entries an earlier file left answer a later file's listing: remembered extension providers show up in `/api/models`, and session rows the next scan calls stale make it persist the index into *that* file's agent dir, which is how a test that counts a folder ends up with a file in it. | Start and end the way a process of your own would: call the module's own reset helper (`lib/__fixtures__/session-scan-index.mjs`) at the top of the file and in `after()`, or `delete` the leftover before and after. |
| Queued microtask work lands before the file's process ends. | It lands during a later file, resolving `process.env` at that moment — so a write aimed at `getAgentDir()` goes wherever the env points then. | Let it land (`await new Promise(setImmediate)`) before resetting the global or restoring `PI_CODING_AGENT_DIR`. The scan-index fixture does the two in that order. |
| `fs.realpathSync` walks directories, so it names a file's real path whatever the file's own permissions: a mode-0 file resolves. | It reads the file, and throws `EACCES` on one it cannot read (`realpathSync.native` is the same call here). | Where a resolved path decides the answer, do not let a failed `realpathSync` mean "no": `isExistingPathWithinRoots()` (`lib/path-security.ts`) takes the parent instead when `lstatSync` says the last component is not a link, which is the same path Node's own `realpath` would have given. Without it a skill document the user cannot read answers 403 "outside the skill folder" here and 500 "could not be read" there. |

`lib/server-shutdown.test.mjs` dispatches the registered signal event directly on Windows: `process.kill()` there terminates the fixture rather than exercising its JavaScript shutdown listener. Unix still uses actual OS signal delivery. The Windows case tests cleanup ordering, duplicate requests and the deadline; it does not claim Unix signal semantics on Windows. `lib/start-supervised.test.mjs` separately exercises real child exits and hard termination, while `lib/crash-diagnostics.integration.test.mjs` verifies that rate-limited SSE warnings still leave every backlog closure on disk.

## Shared i18n context in component tests

Component tests that render `I18nProvider` load the component and provider through jiti with `tryNative: false`. On Windows, jiti's native-import path can use forward slashes while a component's native alias import uses backslashes. Bun can evaluate the same physical `hooks/useI18n.tsx` twice, creating different Context objects: the test supplies one while the component reads the other. Adding `.tsx` or disabling the filesystem cache does not unify those identities. Keep the provider and consuming component in the same jiti module graph, as `MessageView.test.mjs` and `TabBar.test.mjs` already do; do not bypass the provider guard or change production context state to accommodate a test loader. `BranchNavigator.test.mjs` and `ChatInput.test.mjs` exercise actual provider-wrapped rendering as regressions. Tests that alias a shared component dependency must also clear both native and forward-slash Windows cache keys before and after loading, as `SessionSidebar.tabs.test.mjs` does; clearing only the native key can leave the mocked component cached for the next real-provider test.

Leaving `tryNative` out is the same split a full run exposes. A graph that imports a `.tsx` natively takes the native `hooks/useI18n.tsx`, and `bun test` keeps that copy for the whole suite: a component rendered later reads it while its test's Provider came from a jiti graph that evaluated the file again, so only the image, preview and selector cases redden, and only in a full run. Every component test that loads a TSX passes `tryNative: false` (`components/**/*.test.mjs`); a file that forgets it is green alone and red beside its neighbours.

## Writing one

One `*.test.mjs` per area beside its file, the `.ts` under test loaded through jiti with `tsconfigPaths: true` — or by a plain import when every runtime import in its graph names a file with its extension and the module uses no parameter properties (`--experimental-strip-types` refuses those). A file that spawns a child process names `process.execPath`, never `node`: this fork's machines have none.

**Wait for the state, not the clock.** A test that sleeps and then asserts is guessing: on a loaded machine the guess is wrong and the test fails, on an idle one it is right and the test paid for the wait. `lib/__fixtures__/async-wait.mjs` holds the two shapes: `waitFor(condition)` runs until the state the next step needs is there and throws on a deadline, and `settle()` lets the work a call queued run — a few macrotasks, which is the point an assertion that nothing happened yet can be measured from. `lib/mcp-host.test.mjs` is the worked example: 57 `await delay(N)` calls became `waitRegistered()` (the extension may connect the server now), `settle()` where nothing may happen, and, for the idle timer, its own state — `idleReleaseAt` is read instead of waiting 50 ms to watch it not move.

- A window that is the subject is advanced, not slept through: `lib/draft-store.test.mjs` drives its debounce with `t.mock.timers`, which keeps the claim ("a later change does not push the write out") and drops 700 ms.
- An absence is the one wait that stays. "The server does not read ahead of the client" (`app/api/files/backpressure-route.test.mjs`) and "reads do not invalidate the list" (`lib/session-membership.integration.test.mjs`) have no event to wait for, and the alternative path does real IO, so a `settle()` would prove only that it had not started. Where completion is impossible by construction — a lock the test holds itself — a settle is enough, and stronger than the window was.
- A poll is not a sleep: `for (…; !done; …) await …` around the condition the assertion needs is fine at 5–10 ms steps. What is never fine is a `delay` in front of an assertion the code could have signalled.
- **A test never shortens a product promise to go faster.** The lock tests spend about 3.3 s each inside proper-lockfile's retry backoff and the shutdown test 5 s inside its deadline: both constants are promises to a user ("about three seconds of retries, as for `mcp.json`"), asserted by those very tests. A parameter or an environment variable added so a test can shrink them changes the product for the test's convenience. The one seam that was worth it is `getGitStatus(cwd, signal, recentFileMs)`: a file's quiet window is a rule the test asserts, not a promise to anyone, and the route passes nothing.

**A test only one runtime can run is a `skip`, never a silent `return`.** `{ skip: typeof Bun === "undefined" }` shows in the count as skipped; `if (…) return;` reports a pass that tested nothing.

**A test does not read a component's source to assert its wiring.** `readFileSync` on a `.tsx` and a regex over it breaks on a rename that changed no behaviour, and it proves nothing a rendered assertion could not: the hints a menu draws, the keys it uses and the marks it carries are all in `renderToStaticMarkup`'s output. Where wiring cannot be observed that way — which handler a click reaches, which prop a component forwards, which directory a reopened child's wrapper registers a rule for — it stays untested and the comment says so; a click belongs to a browser test. `lib/bash-command-normalize.test.mjs` keeps the one exception, named there: a wrapper handed the parent's cwd would silently strip nothing in a child's tab, and no test can build that wrapper without a real child session.

**One rule is checked once, not once per file that grew it.** A cross-file rule — the client graph's syntax for Safari 16.2 (`components/client-syntax.test.mjs` scans every component and hook), the import extensions of `components/test-imports.test.mjs` — belongs to a scan of the tree, not to a copy in each component's own test; a component's own test keeps what is its own (its CSS section, its markup). A per-component copy is what grew the lookbehind check to five files.

**Whatever a file changes about the process, it puts back in its own `after()`.** Under `bun test` the suite is one process. A module-scope `process.env` write (`GIT_CONFIG_GLOBAL`, `XDG_CONFIG_HOME`, `PI_CODING_AGENT_DIR`) leaves every later test working inside a fixture directory this file deleted, and Node's per-file process hides exactly that, so CI stays green while the local run rots. The same holds for `globalThis` and the module registry: capture a key's original once, on the first swap of it, so the last restore cannot write back a stub an earlier swap installed (`lib/__fixtures__/pi-global-swap.mjs`).

A file that arrives from upstream is written for Node's isolation — one process, one module registry, `tryNative` off — so it lands red here until it takes that same treatment: `tryNative: false`, the modules it stubs dropped from the require cache before jiti loads it and again in `after()`, and whatever it leaves on `globalThis` taken back afterwards. A `fetch` or `EventSource` stub that outlives its own file answers the next file's real request, and the failure surfaces there: `url.startsWith is not a function`, or a request the harness never made.

**A fixture that runs Git gives each command that writes one a name and an address, and never swallows the command's own failure.** GitHub's runner carries no `user.name` and no `user.email`, so a write answers `fatal: empty ident name … not allowed`; a repository fixture passes `-c user.name=… -c user.email=…` on every commit — the merge that produces a conflict included, since a merge commits. And the state a fixture builds is asserted before the product is: `try { git merge } catch {}` reads "the merge conflicted" and "Git refused to merge" as one outcome, so the assertion two lines later reports the route's answer — `supported: false` — when what happened is that no conflict was ever made. Read what the fixture left (`git status --porcelain` names the `UU` the case is about) and put the command's own output in that guard's message.

## Reading a failure

- Red when the file runs alone (`bun test path/to/x.test.mjs`) → that file is not Bun-ready: a `node:module` export that is not there, or real React because an alias was bypassed.
- Red alone as well as in a full run, on a machine whose `PATH` holds no `node` → the file spawns `node` by name, and the missing executable surfaces as whatever the dead command left behind: a parse failure on the output that never arrived, or a pid file that was never written. Spawn `process.execPath` instead — the interpreter the suite itself runs on, so the child is bun under `bun test` and node under `npm test`.
- Red only in a full run → an earlier file left something behind, or this one did. The usual signature is a scripted fetch answering the next file's real request: a server that should be reached reads `failed` with `no answer scripted for POST http://127.0.0.1:<port>/mcp`, `url.startsWith is not a function` coming from a hook test's stub, or a folder holding one file more than it was written.
- **A file that fails and then never exits** — the job hangs instead of reporting, and Node's last line is `Promise resolution is still pending but the event loop has already resolved` — is usually an open stream or process. `lib/agent-event-stream.test.mjs` was both at once: a session's `connected` event grew a field the file asserted exactly, and the helper that opens its streams asserted that shape before anything could close them, so sixteen failures each left a stream pending and the file's process never ended. A helper that opens one registers its close with a file-level `after()` before it asserts anything, so the same failure next time reports itself.
- Before fixing anything, check whether it is upstream's: `git worktree add --detach /tmp/x origin/main`, symlink this `node_modules` in, run the same command there. Upstream's own tree is nowhere near green under Bun, which is the point of this fork, not a reason to copy it.
- Red in this checkout and green in a worktree of the same commit is the checkout talking, not the commit. `bun test` loads the folder's own `.env`, so a `PI_WEB_PASSWORD` written for the dev server reaches `lib/web-auth.test.mjs`, and the shell's exported variables reach what else a test asks the environment (`lib/project-command-env.test.mjs`); `bun test --no-env-file` takes that away. A `dist/` left by a build adds tests of a bundle that is not the tree's (`dist/client/sw.test.mjs`) to a run that counts files. Judge the run by the files you touched: what names none of the files you are committing is CI's to judge (CI installs from `package-lock.json` with `npm ci` and runs `npm test`, with no `.env` and no `dist/` of anyone's), so it goes there rather than being chased here.

## Assertions an engine cannot all produce

Some messages come from the engine, not from us, and the two engines word them differently: V8 quotes the text around a `JSON.parse` break and gives a position, JavaScriptCore words the same break differently and quotes less. A test that pins one engine's exact rewording fails the other runner and pins nothing about us. So the guarantee is asserted engine-independently — `jsonErrorMessage()` names the format and none of the file's text, which is often a literal secret — and the exact wording is pinned only where that engine parses. The same split covers ICU: zh-TW assertions accept either spacing. An absence check reads the message the module produced rather than the string it expected, so the invariant is really exercised on both runners. (`9e49400`; upstream's suite never meets this, because it only runs on one engine.)

## Documentation is under test

`lib/markdown-emphasis.test.mjs` renders every `*.md` in the repository with CommonMark and fails the suite if a `**` survives into the prose: `**…全绿。**下面` is neither left- nor right-flanking, so GitHub prints the asterisks. The rules are quoted in `lib/markdown-emphasis.ts`.

Two things make this more than a grep for `**`. The app forgives this shape — `lib/markdown.ts` loads `remark-cjk-friendly`, pinned by `components/MarkdownBody.test.mjs` — so the gate renders with no remark plugins. And a pairing heuristic misfires in both directions: `**Two ways to branch**: **New session** … **Edit from here** …` is ordinary Markdown, while `请打开**（模型）**面板登录。` refuses both roles and has no partner to name. So the parser judges and the rules only say which role was refused.

Ask git for the file list with `execFileSync("git", ["ls-files", "-z", "--", "*.md"])`: through a shell the glob expands in the repository root first, and the scan shrinks to six files without failing anything.

`lib/readme-sync.test.mjs` holds the translated README to the English one and resolves every relative link in the repository's Markdown; the rules are `lib/readme-sync.ts`.

- What the Chinese copy must keep is counted, never read: the same `## ` and `### ` sections, the same number of `- ` items and `**claim**` paragraphs in each, and the same claims in the same order. A claim is identified by the note it links, because its sentence is translated — `./docs/agents/sessions.md#a-b` in `README.md` and `./agents/sessions.md#a-b` in `docs/README.zh-CN.md` are the same claim, one directory apart. Comparing headings by name would compare nothing, and comparing prose would compare wording that is free to differ. What this caught on its first run: an entry deleted from `README.md` when upstream took the feature while the Chinese entry stayed, two entries never translated, and a `### Docker` plus two `## Notes` subsections that the Chinese copy simply never carried.
- A fragment must name a heading, by GitHub's rules (`githubSlug()`): lowercase, punctuation deleted, every remaining space a hyphen — which is why `Settings › Tools` is `#settings--tools` with two hyphens, and why collapsing runs of whitespace in the slug breaks nine links at once. A code span keeps its words in a heading's anchor and is not a link where it sits, so a line is read twice, as `plain` and as `text`; that is what makes the `](#s2)` inside a code span — an example of an HTML anchor, not a link — invisible to the check.
- A note's headings are names, so a repeat is refused in `docs/agents/*.md` whether or not anything links it: a repeated heading resolves to its first anchor, so a link can name one section and land in its twin — which is how a sync that left two copies of `## Which lines wrap` in `docs/agents/files-and-access.md` satisfied every link check. Outside the notes a heading is a name only while something links it, so `docs/release.md` keeps its two `## 中文` sections, one per release-notes template.
- Translated copies sit one directory down, so their paths differ and a careless copy of a link reaches nothing: `docs/README.ja.md` and `docs/README.ru.md` pointed at `./README.md`, which is `docs/README.md`, and no reader reported the dead link.

## e2e (Playwright)

### What a normal test owns first

Before writing a browser check, ask what it asserts. Logic, a request body, a route's answer, a pure function or a component's markup is a `*.test.mjs` on both runners; only what an engine alone can show — layout and geometry, paint, CSS, real focus and pointer input, a live stream, a page's wiring — needs WebKit. `e2e/run.mjs` long carried the opposite: bounding the detail, following a leaf, paging to the root, the external-append `?force=1` read and a files 403 were plain `fetch` calls beside a server the suite happened to start, and never touched the page. They are `app/api/sessions/[id]/context-route.test.mjs` and `[id]/detail-route.test.mjs` now, where a route's answer belongs.

The rule cuts both ways, and the second half is the one that bites: a claim about what a reader sees is measured where it is applied, never re-derived from source. Do not stage a rendering effect in a unit test to dodge the browser — the palette's WCAG ratios stay a contrast loop over `getComputedStyle` in `e2e/themes.mjs`, because the theme block a token is declared in is not the block that applies to it: a later `:root`, a media query or an inherited value changes the computed colour while the declaration reads the same. Reading `app/globals.css` would keep the arithmetic and lose the question.

`npm run test:e2e` runs `e2e/run.mjs`: it spawns its own server through vinext on a free port (never the dev server), drives Apple WebKit at 1280px and 390px viewports, and writes screenshots into an artifacts folder. Build first — it tests the production bundle, so a source change that has not been built is not what runs. Upstream drives Chromium and installs `--with-deps chromium` in its CI; this branch installs and runs no Chromium binary. The e2e job runs inside Playwright's own image (`mcr.microsoft.com/playwright:v<version>-noble`), which carries the WebKit build matching the lockfile's `playwright` version together with its Linux libraries, so the runner installs neither: a `playwright-version` job reads that version out of `package-lock.json` (and fails the run rather than pulling a tag that names no version), the container tag follows it, and the `-noble` suffix — published from Playwright 1.44 on, so an older pin needs `-jammy` — is the one part a version bump does not carry. The image presets `PLAYWRIGHT_BROWSERS_PATH=/ms-playwright`, and `e2e/browser.mjs` overrides that variable only on darwin, so CI launches the image's copy. `npm run test:e2e:install` fetches the WebKit build into `~/Library/Caches/pi-browsers` on macOS and into Playwright's default registry everywhere else. `e2e/browser.mjs` is the only module that launches a browser: import `launchBrowser` and `newTestContext` from it, never a browser type from `playwright`. `PI_WEB_BROWSERS` moves the macOS directory.

**No number a check writes down is a pixel of the interface.** A position comes from the box the check already has (`locator.boundingBox()`, `getBoundingClientRect()`); a tolerance comes from the thing it tolerates (a row's own height); how far to scroll comes from the scroller's `clientHeight`. A literal coordinate is left to one job only — parking the pointer out of the way (`mouse.move(0, 0)`) — because every literal is either a place the layout no longer has or a number that was never the promise, and either one reddens the suite on a change nobody can see. The suite had three: a menu dismissed by clicking `(width - 10, 850)`, a drag dropped at `y: 4`, and a reading position pinned to `- 120px` and to the exact `clientHeight * 0.3` a click should land on. The assertions that remain are comparisons the check derives: the input is no taller than its row, the entry a preview click names is inside the scroller's upper half, the restored offset is within one row of where it was.

Screenshots are evidence, not assertions: a check writes them for whoever opens the failure artifact and asserts nothing about what they show.

**A check must not be able to pass on a fast machine and fail on a loaded one.** That rules out a method, not just a slow line: a `count()` or `isVisible()` taken on the line after the click that mounts what it counts reads the absence and calls it a failure (the Settings dialog mounts after its button's click answers — `e2e/themes.mjs` failed twice on that shape); a value the app keeps updating, sampled once at whatever moment the check got there; a timeout used as evidence that something finished; an order the modules happen not to collide in today. The replacement is a state the check can name and wait for — the dialog is visible, the sentinel is detached, the row is in the scroller — and, where a value is stored in a form the app normalises, the app's own reading of it (`localStorage.getItem("pi-theme") ?? "auto"`, because choosing the default writes nothing). A check that needs a particular machine's speed to be green is a flake waiting for CI's runner.

**A check that has not run has not been checked.** `e2e/themes.mjs` was written, then left without an entry point, and every way it could rot, it had: it asked for an icon on every theme option after the options had become swatches; it drove a `Theme:` toolbar menu that had moved into Settings' radiogroups, which this note records as handled; it counted those options from the line right after the click that mounts the dialog; it required the fork's dark ink to stay neutral gray, which the fork's design layer tints; and it read the stored preference as the theme id, though choosing the default writes nothing. It is `npm run test:e2e:themes` now (manual, against a server of this tree; CI does not run it), and the palette's WCAG loop lives in it. A manual suite earns its keep only while someone runs it — and a `vinext start` of an older build answers like a newer one until it meets markup that moved.

- The palette has two floors, because it has two kinds of text: body copy and the accent that carries links hold 4.5, while `--text-muted` and `--text-dim` — a timestamp, a directory name, a metadata line — hold 3.0. That second floor is this suite's own promise and not AA, which asks 4.5 of text at any size; it is written down in the check because the tier is a deliberate de-emphasis rather than an oversight. Against one 4.5 floor the palette had 36 failing pairs and nothing knew it, because nothing ran the loop. With the two floors it has three, kept in `KNOWN_GAPS` so a run names them and a new one fails: `--accent` on `--bg-selected` at 4.39 in the two light palettes, and zenburn's `--text-dim` on its own `--user-bg` at 2.28 — the one value a shared dim cannot carry, since `app/new_design.css` overrides every palette's `--text-dim`, zenburn's own lifted one included.

- Run it the way CI runs it: `npm run build`, then `E2E_SERVER_MODE=start` (CI does exactly that, `ci.yml`), because that is the bundle a reader gets.
