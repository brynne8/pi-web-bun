# Tests

`bun test` is the target; `npm test` (Node's runner, the `test` script) is the second opinion, and upstream only has that one — so a rebase onto upstream always brings the work in this note. Compare failures, never totals: Node counts subtests and suites of its own accord, so the same tree reads roughly 2,821 tests on Bun and 2,865 on Node — 323 files and one skip either way. Both totals fell by a few hundred upstream's `f364bc3`, which dropped the assertions that restated a component's source text.

## What behaves differently under Bun, and what to use instead

| Node | Bun | Use |
| --- | --- | --- |
| One process, one `globalThis`, one module registry **per test file**. | One of each for the **whole suite**, files in sequence. | Whatever a file puts on `globalThis` or into the registry, it hands back in `after()` (`node:test`). A file that never restores is the next file's failure. |
| jiti `tryNative` off, so jiti resolves every import. | jiti detects Bun and turns `tryNative` on: the module is imported natively, its `import`s answered by Bun — an `alias` never applies, and jiti hands back Bun's sealed ESM namespace. | `createJiti(url, { tryNative: false })`; add `interopDefault: false` to write into a module's exports. |
| A module two files load: each gets its own copy. | The same instance, with whatever the first file left on it. | `delete createRequire(import.meta.url).cache[realpathSync(fileURLToPath(...))]` for each module the file stubs, before jiti loads it. |
| A source `.ts` that imports a sibling by its extensionless name reaches a test only through a loader that fills the extension in. | Bun resolves the extensionless path, so a test's direct `import … from "./x.ts"` is green here and says nothing about Node, where the file dies with `ERR_MODULE_NOT_FOUND` before its first test. | Load the module under test through jiti (`createJiti(import.meta.url, { tsconfigPaths: true })`, then `await jiti.import("./x.ts")`). Source files keep their extensionless imports — that is the convention, and the bundler is the target runtime. |
| `import { readFile } from "node:fs"` reads a live property, so `t.mock.method(fs, "readFile")` reaches it. | A named builtin import is bound to a frozen snapshot: the mock never lands. | Import the builtin's default and read `fs.readFile` at call time. |
| `module.stripTypeScriptTypes()`. | Not exported, and not a global. | `runStripped(code, context)` from `lib/__fixtures__/strip-types.mjs` — jiti's transform, one path on both runtimes, and unlike Bun's own transpiler it keeps a top-level function expression as the completion value. |
| `module.registerHooks()` to answer a `.module.css` import. | Not exported; Bun loads CSS modules itself. | Install the hook only `typeof registerHooks === "function"`. |
| `fetch` goes through undici's global dispatcher, and jiti's CJS interop finds `undici.install` so `configureHttpDispatcher()` can point fetch at it. | Bun's own `fetch`: it installs no dispatcher (`configureHttpDispatcher()` is a no-op here), takes its proxy from the request or `$HTTP_PROXY` / `$HTTPS_PROXY` — for `127.0.0.1` too — and resolves no `install` out of `undici`, so `undici.install?.()` would skip silently. | Prove a port is closed with `connect()` from `node:net`, never with `fetch`. Assert the dispatcher's contract on Node only, and say so in the test. Never let an optional call be the only thing that makes a branch work on one runtime. |
| No per-test timeout by default. | 5 s. | `{ timeout: … }` where a test waits on something genuinely slow. |
| A keep-alive connection a proxy recycles just ends the request. | `node:http` errors the request stream, so a fixture server that reads `req.body` unguarded raises an unhandled rejection — attributed to whichever test is running. | Guard the body read in the fixture (`lib/__fixtures__/mcp-oauth-server.mjs`). |
| The product state a module keeps on `globalThis` (`__piWebScanIndex`, `__piWebProviderModelCatalog`, `__piWebTerminals`, …) is that file's alone. | It is the suite's. Entries an earlier file left answer a later file's listing: remembered extension providers show up in `/api/models`, and session rows the next scan calls stale make it persist the index into *that* file's agent dir, which is how a test that counts a folder ends up with a file in it. | Start and end the way a process of your own would: call the module's own reset helper (`lib/__fixtures__/session-scan-index.mjs`) at the top of the file and in `after()`, or `delete` the leftover before and after. |
| Queued microtask work lands before the file's process ends. | It lands during a later file, resolving `process.env` at that moment — so a write aimed at `getAgentDir()` goes wherever the env points then. | Let it land (`await new Promise(setImmediate)`) before resetting the global or restoring `PI_CODING_AGENT_DIR`. The scan-index fixture does the two in that order. |

## Reading a failure

- Red when the file runs alone (`bun test path/to/x.test.mjs`) → that file is not Bun-ready: a `node:module` export that is not there, or real React because an alias was bypassed.
- Red alone as well as in a full run, on a machine whose `PATH` holds no `node` → the file spawns `node` by name, and the missing executable surfaces as whatever the dead command left behind: a parse failure on the output that never arrived, or a pid file that was never written. Spawn `process.execPath` instead — the interpreter the suite itself runs on, so the child is bun under `bun test` and node under `npm test`.
- Red only in a full run → an earlier file left something behind, or this one did. The usual signature is a scripted fetch answering the next file's real request: a server that should be reached reads `failed` with `no answer scripted for POST http://127.0.0.1:<port>/mcp`, `url.startsWith is not a function` coming from a hook test's stub, or a folder holding one file more than it was written.
- Before fixing anything, check whether it is upstream's: `git worktree add --detach /tmp/x origin/main`, symlink this `node_modules` in, run the same command there. Upstream's own tree is nowhere near green under Bun, which is the point of this fork, not a reason to copy it.

## Writing one

One `*.test.mjs` per area beside its file, the `.ts` under test loaded through jiti with `tsconfigPaths: true`. Never write to `globalThis` at module scope without the matching `after()`, and never assume the file has the process to itself. A file that arrives from upstream is written for Node's isolation — one process, one module registry, `tryNative` off — so it lands red here until it takes the same treatment: `tryNative: false`, the modules it stubs dropped from the require cache before jiti loads them and again in `after()`, and whatever it leaves on `globalThis` taken back afterwards. Three did after the sidebar merge: `hooks/useSidebarMotion.test.mjs`, `hooks/useResizablePanel.test.mjs` and `components/SessionSidebar.tabs.test.mjs`, all of which alias `react` to the hook shim or `hooks/useFilesPlacement` to a fixture. Three more did after the origin merge of 2026-10-11: `hooks/useAudio.test.mjs` (the hook shim alias, plus `useAudio.ts` dropped from the cache because an earlier file may have loaded it natively), `components/AppShell.workspace-memory.test.mjs` (its `vm.runInContext(stripTypeScriptTypes(…))` became `runStripped(…)`), and `lib/prism-languages.test.mjs` (its module dropped from the cache, and the cold-start assertion on `refractor.registered()` removed: `refractor/core` is one instance for the process, so any file that rendered highlighted code first has already registered every language — that start is only observable under Node's per-file process). `lib/markdown.test.mjs` joined them for a different reason: a test may import a source `.ts` directly only as long as that file imports nothing of its own, and `lib/markdown.ts` grew the `lib/markdown-prose-math.ts` import. A file that spawns a child process never names `node`, either: this fork's machines have none, so it spawns `process.execPath`, which is bun under `bun test` and node under `npm test`. `lib/project-command-env.test.mjs` prints the environment its bash tool's child sees that way, and `lib/__fixtures__/mcp-env-server.mjs` starts its detached writer that way — the child is what those tests are about, so there is nothing to evaluate in the test's own process instead.

## Assertions an engine cannot all produce

Some messages come from the engine, not from us, and the two engines word them differently: V8 quotes the text around a `JSON.parse` break and gives a position, JavaScriptCore words the same break differently and quotes less. A test that pins one engine's exact rewording fails the other runner and pins nothing about us. So the guarantee is asserted engine-independently — `jsonErrorMessage()` names the format and none of the file's text, which is often a literal secret — and the exact wording is pinned only where that engine parses. The same split covers ICU: zh-TW assertions accept either spacing. An absence check reads the message the module produced rather than the string it expected, so the invariant is really exercised on both runners. (`9e49400`; upstream's suite never meets this, because it only runs on one engine.)

## Documentation is under test

`lib/markdown-emphasis.test.mjs` renders every `*.md` in the repository with CommonMark and fails the suite if a `**` survives into the prose: `**…全绿。**下面` is neither left- nor right-flanking, so GitHub prints the asterisks. The rules are quoted in `lib/markdown-emphasis.ts`.

Two things make this more than a grep for `**`. The app forgives this shape — `lib/markdown.ts` loads `remark-cjk-friendly`, pinned by `components/MarkdownBody.test.mjs` — so the gate renders with no remark plugins. And a pairing heuristic misfires in both directions: `**Two ways to branch**: **New session** … **Edit from here** …` is ordinary Markdown, while `请打开**（模型）**面板登录。` refuses both roles and has no partner to name. So the parser judges and the rules only say which role was refused.

Ask git for the file list with `execFileSync("git", ["ls-files", "-z", "--", "*.md"])`: through a shell the glob expands in the repository root first, and the scan shrinks to six files without failing anything.

## e2e (Playwright)

`npm run test:e2e` runs `e2e/run.mjs`: it spawns its own Next server on a free port (never the dev server), drives Apple WebKit at 1280px and 390px viewports, and writes screenshots into an artifacts folder. Build first — it tests the production bundle, so a source change that has not been built is not what runs. Upstream drives Chromium and installs `--with-deps chromium` in its CI; this branch installs and runs no Chromium binary, so CI installs `--with-deps webkit` and `npm run test:e2e:install` fetches the WebKit build into `~/Library/Caches/pi-browsers` on macOS and into Playwright's default registry everywhere else. `e2e/browser.mjs` is the only module that launches a browser: import `launchBrowser` and `newTestContext` from it, never a browser type from `playwright`. `PI_WEB_BROWSERS` moves the macOS directory.

- The suite is upstream's, and it pins **upstream's rendering**. Where this fork's rendering differs by design, the assertion is removed rather than rewritten to the branch's number: how many "Process details" folds a turn has is one per run of thinking and tool calls here and one per turn upstream, and a count asserted here would need editing every time the segmentation rule moves. What stays asserted is what is true either way — thinking never stands on its own outside a fold, the turn's model label appears once, long table cells wrap while wide tables scroll, and a tool card expands to its output. Reaching a tool card opens the folds without asserting how many there were.
- Older history is asked for the way a user asks for it: the sentinel scrolling into view. Re-opening a session does **not** fetch an older page on its own, because the lazy window counts messages and the loaded content is already tall enough to restore the reading position into. A test that waits for a fetch on session open is waiting for the window bug that used to cut the top off.
- Two failures only this suite could catch, both worth remembering as the shape of thing e2e is for: a prepended older page whose first message was missing from the DOM (the window counting rendered entries instead of messages), and a model label printed once per part of one entry (a part carries the whole entry's provider, so the label repeated down the turn).
- WebKit is published for Windows (`win64`), for Ubuntu 22.04 / 24.04 / 26.04 in x64 and arm64, and for WSL, so a Windows or Linux developer loses nothing but one step: on Linux the system libraries come from `sudo npx playwright install --with-deps webkit`, which CI does anyway.
- `newTestContext()` blocks service workers. Production registers `/sw.js` with `scope: "/"`, and a worker that controls the origin answers app requests without ever handing them to `page.route()` — the request event still fires, so the failure reads like a broken matcher. The suite drives the app, not the PWA shell.
- Console errors and uncaught errors reach one allowlist in `e2e/run.mjs`, narrowed to what the harness causes or what an engine reports while tearing a page down. Both channels feed the same check because which one carries a given failure is the engine's choice. The third thing it holds is what one platform's build prints about a key another platform's build accepts quietly: the Linux WebKit CI image logs `Viewport argument key "interactive-widget" not recognized and ignored.` at error level, once per parse, for the Chromium-only virtual-keyboard key `app/layout.tsx` sets on purpose, while the macOS build of the same revision reads that same tag and says nothing at any level. The pattern is pinned to that key and that sentence so it cannot cover a real error.
- A value the page keeps updating is read until it stops moving before anything is asserted: the minimap's turn count after an older page is prepended, and the sidebar's Show/Hide toggle after a breakpoint change. Both are ordinary races that one engine's timing happened to hide.
- An assertion follows the control, not the control's old shape. Theme and language picking moved out of a toolbar menu into Settings' radiogroups, so the menu's own geometry and icon count went with the menu while what it was proving is asserted where it lives now: one theme selected at a time, and opening the panel does not change one (`themes.mjs`); Escape closing without reaching the global shortcut, focus back on the opener, arrow keys and Home/End roving the items, and the popup fitting the viewport (the session row's menu, in `session-navigation.mjs`). A check is not dropped because its widget changed form.
- Two facts about that menu were measured rather than assumed: it focuses its first item as it opens, so ArrowDown lands on the second, and ArrowUp from the first wraps to the last. Item names are read with `innerText`, since the shortcut hint sits on its own line and `textContent` would glue "Pin" to its hint.
- Middle-click opening a session in a new tab is not asserted: Playwright's WebKit shell opens no page for a middle-click (a modified click does open one), so the half the suite can prove is the app's own contract — the row is a real link carrying no `target`, which is what lets a browser act on it — and the gesture itself belongs to a browser that has it.
- A pointer click names a place on the screen, so a test that clicks a control which draws something over itself on hover cannot rely on that control's geometric centre. The sidebar's file row was that case: its name span is `flex: 1` (`components/FileExplorer.tsx`), so the span's box ran under the hover-only mention and download buttons and the row's centre fell inside the mention button — which is how the file-panel check came to fail with a real pointer click on WebKit while another engine got through: when a foreign element intercepts the click Playwright reports it and retries until the timeout, so what you see depends on where the pointer already rested. The reason is gone now in the app, not just in the test: a row's actions moved to its right-click menu (see `A row's own actions` in [files-and-access.md](files-and-access.md)), so the middle of a row is the file's again and `e2e/file-panel.mjs` clicks it with a real pointer. `e2e/file-row-menu.mjs` pins what that menu holds, and asserts the centre of a hovered row is the file's own name (`data-file-row-path`, not a button); it never clicks the file-manager item, since raising a real Finder window on whoever runs the suite is not a test. What a check must not do is name a pixel on a row that has actions of its own — neither a coordinate nor "the middle, assuming nothing else is there".
- A height that must change is a claim about the fonts installed here, not about the app. `checkFontPreferences` changed the interface font from `serif` to `monospace` and waited for the draft box to change height. On a runner whose two generic families wrap that draft into the same number of lines there is no change to wait for, so it spent the whole timeout and reported a `TimeoutError` with nothing measured in it (`log: []`), while on a Mac — where the same draft is 90px under serif and 112px under monospace — it passed for the right reason. What is asserted now is what a reader can see: the box fits what the family it is drawn in needs. The direction that must move the height is asserted where the change guarantees a metric change, at the width and font-size sliders in `e2e/chat-appearance.mjs`. Both heights are printed on every run, so the log says which of the two worlds a machine turned out to be in, and a failure carries them in its message.
- One failure stays red on purpose. `npm run test:terminal` (a manual suite, not in CI) asserts that a monospace font chosen in Settings reaches an already-open terminal, and under WebKit it does not: the choice does land in `pi-mono-font-family` and in `--font-mono`, but xterm keeps the stack it read when the terminal was created, and on the 390px path nothing re-reads it. Chromium's timing hides the gap, so this is an app difference a Safari user can see, not a test artefact.
